# Converge Codebase

既存の振る舞いと外部契約を守りながら、対象範囲を定義した目標状態へ移行する。監査結果を並べるだけで終わらず、旧経路と移行用の一時物を撤去して全体完了まで確認する。

## Workflow

1. **目標と範囲を固定する**。収束させる設計上の目標、対象ファイル・経路、維持する外部契約、対象外を明記する。プロジェクトの契約がなければ docs・CI・tests・既存の設定から根拠付きで抽出し、重要な不明点だけ質問する。
2. **変更前の基準を取得する**。対象の既存違反一覧と関連 test の baseline を変更前に記録する。既存の収束計画があればそれを読み込んで再開し、新しい重複 plan を作らない。
3. **現状を監査する**。対象の呼び出し元、設定経路、動的参照、外部利用、互換層、重複実装、旧経路、一時コードを調べる。利用可能なら `ponytail-audit` や適切な architecture/review Skill を使い、欠落していても同等の棚卸しを行う。違反総数だけでなく、新規違反が追加されていないかを確認する。
4. **living plan をプロジェクト内に置く**。既存 plan を再利用して、段階ごとの移行単位、検証方法、残る旧経路、撤去条件、未解決の前提を記録する。計画は進捗に合わせて更新し、部分完了と全体完了を分ける。
5. **小さく移行する**。各段階で振る舞い・外部契約・安全性を保つ変更を行い、段階ごとに関連 test・lint・型検査・動作確認を実行する。既存実装の再利用は要求とプロジェクト契約に適合する場合に限る。必要な一時経路や互換層を置く場合は、撤去条件を同じ計画に書く。
6. **旧経路を撤去する**。新経路への移行後、静的参照だけでなく設定・動的参照・外部利用・運用手順を確認して旧経路と一時物を削除する。未使用に見えるコードを、動的参照や外部契約の調査なしに削除しない。
7. **全体を検証する**。目標状態、対象範囲、契約、全段階の検証結果、旧経路・一時物の撤去、新規違反がないことを確認する。実装者とは別の独立レビュー工程を必ず行い、利用可能なら architecture/code/security review Skill を使い、なければ同等の別工程で確認する。Issue 分割、PR 作成、配備は依頼されていない限り行わない。

## Completion

次の全てを満たしたときだけ全体完了とする。

- 目標状態と対象範囲が明記され、計画と実装が一致している。
- 各移行段階の検証結果と、変更前からの失敗・未検査が区別されている。
- 旧経路と撤去対象の一時物が、動的参照・設定・外部契約を確認したうえで削除されている。
- 違反総数の減少だけでなく、新規違反が追加されていないことを確認している。
- 対象の契約を確認するための検証が済み、今回の回帰がない。変更前からの対象外の失敗は、今回の検証を妨げない根拠を記録する。必要な検証ができない場合や、撤去対象の旧経路について外部利用が確認できない場合は未完了とする。
- 独立レビューで未解決の重大な指摘がなく、残作業があれば全体完了ではなく部分完了として報告している。
